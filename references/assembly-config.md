# 应用层组装配置（Assembly Config）

> **依赖与前置**
> - 前置：`metric-library.md`（指标已定）、`tree-aggregation.md`（聚合）、`anomaly-todo.md`（监控）、`permission.md`（权限）
> - 被依赖：`acceptance-checklist.md`（按本表的验收标准验收）
> - 覆盖阶段 5：把指标库 + 数据组装成成品看板

散落的零件（导入/聚合/图表/监控/权限）在这步拼成成品。一张《应用层组装配置表》，四维逐项选配，**每个选配项同步写一条「验收标准」**。

## 核心：验收标准先行

选配一个功能，同时写下「怎么算验好了」。验收标准写成**用户视角的结果**，不是「代码做了什么」：

- ✅ 「游客看不到受限按钮」「筛选后表格真变」「导出文件离线打开」
- ❌ 「applyPermissions 被调用」「filter 函数执行了」

组装表结构：

| 模块 | 选配项 | 选项值 | 验收标准 |
|------|--------|--------|---------|
| 经营日报 | 导出 | HTML快照 | 导出文件离线打开、图表转PNG、无script |

## 四维选配

### 1. 功能选配（数据进出）

| 功能 | 默认建议 |
|------|---------|
| Excel/CSV 导入 | 数据人工更新→要 |
| 数据库直连 / API 拉取 | 有现成库/接口→要 |
| 导出 HTML 快照 | 汇报型→要 |
| 导出 PNG 长图/卡片 | 发群/PPT→要 |
| 上传云端持久化 | 多人共享→要 |
| 历史数据查询 | 按日期回看→要 |
| 导出 Excel/CSV 明细 | 运营要拿数分析→要 |

### 2. 呈现方式选配（图表 × 场景）

| 呈现方式 | 适用 |
|---------|------|
| KPI 指标卡 | 单一核心数（总量/占比/达成率） |
| 明细表格 | 精确读数、多列对比、下钻明细 |
| 排行榜（横向条形 Top N） | 排名 |
| 柱状图 | 分类对比 |
| 折线图/趋势图 | 时间序列（需多天数据） |
| 堆积柱/堆积面积 | 构成占比 + 总量 |
| 饼图/环形图 | 单层占比 |

维度配置：呈现范围（entity_l1/l2/l3 层级）+ 筛选器（时间/层级/维度，级联）+ 视角切换（多维度切树）。

**交互能力（每种呈现形式都要配，决定可用性和便利性）**：

| 交互 | 说明 |
|------|------|
| **默认折叠（首选）** | 多层级数据默认收起子级、只显示顶层，点击逐级展开。**别一次性平铺全部明细**（360 行平铺，数据再准也没法用）。这是明细表格/树形数据的默认交互方式 |
| 排序 | 表格、排行榜点表头排序 |
| 搜索/筛选 | 明细多、要定位 |
| 分页/虚拟滚动 | 数据量大（几千行+），避免一屏卡死 |

> 核心原则：**呈现形式不止「画什么」，还有「怎么交互」**。选配每个呈现方式时，同步确认它的交互（折叠/排序/筛选/分页）。一张平铺的长表格 = 完成了功能、没完成可用性。

### 3. 异常监控

- 规则清单（阈值/优先级/策略，见 `anomaly-todo.md`）
- **提醒方式**：站内徽标（红点计数）/ 待办清单 / 邮件 / 企微·钉钉 webhook，按紧急度分级触发（低→站内，高→推送）
- 待办：分组归类 + 详情弹窗

### 4. 部署权限

- 部署形态：纯前端 / 云函数 / 自建服务器 / MySQL（见 `cloud-deploy.md`）
- 权限：三级（admin/whitelist/guest）+ 按钮级 data-auth（见 `permission.md`）
- 数据级权限：行级过滤（不同角色看不同实体范围），主流产品标配，可选

## 真实示例

见 demo-dss 的 `assembly-config.md`——经营日报的完整组装表（12 个 ✅ 选项各配验收标准，本地演示版不启用上传云端/历史/邮件推送等需后端的功能）。

## 真实坑

1. **视角切换要同步刷新筛选器**：切视角重建树后，三级筛选器必须重建，否则停在旧维度（经营日报案例踩过）
2. **异常规则 enabled 字段**：规则对象漏了 `enabled`，`!undefined` 会把规则全跳过、异常永远 0。用「默认启用，仅显式 0 才禁用」判断（见 `anomaly-todo.md`）
3. **趋势图依赖多天数据**：单天数据画不了趋势，选配趋势图前先确认有历史数据来源（云端快照或本地多份）
