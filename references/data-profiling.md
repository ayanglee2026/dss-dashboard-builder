# 数据画像检查清单（Data Profiling）

> **依赖与前置**
> - 前置：`domain-mapping.md`（识别业务实体层级 / 唯一 ID 用哪个字段）
> - 被依赖：`metric-dictionary.md`（画像字段 → 口径表直接字段）、`excel-import.md`（画像发现的清洗规则）
> - 可独立读。开工时第一个读的就是这篇。

数据驱动任务的第一步。**拿到数据不要直接写逻辑，先看数据长什么样、有没有坑。**

## 输出物

一张《数据画像表》，给用户确认后再进入下一步。

## 检查清单

### 1. 结构层面
- [ ] 字段清单：一共几列？每列是什么类型（文本/数字/日期/布尔）？
- [ ] 行列规模：多少行数据？多少条记录？
- [ ] 主键：有没有唯一标识？（没有的话，聚合时用什么做 key？）

### 2. 质量层面（默认有坑，逐项验证）
- [ ] **缺失/空值**：哪些列有空白？占比多少？
- [ ] **异常值**：负数（不该有的）、超大值、超小值、0 占比异常高
  - **超大值/超小值判据**：`值 > 该列中位数 × 10` 或 `超出业务上限`（口径表定义的合理范围）→ 标记「待确认」，不得直接参与聚合
  - 负数：口径不允许负的列出现负值 → 标记
  - 0 占比异常高（>30%）→ 确认是真 0，还是缺省值被填成了 0
- [ ] **格式不一致**：
  - 同列混多种格式（如日期有 `2026/7/1` 和 `2026-07-01`）
  - 数字列混进文本（如 `"1,200"`、`"约200"`、`"--"`）
  - 表头有全角括号、多余空格、换行符（`normalizeHeader` 要处理）
- [ ] **重复**：同一行出现两次？同 key 出现两次（会静默覆盖/累加）？
- [ ] **脏值占位**：`-`、`--`、`NULL`、`(null)`、空字符串当成了真数据？

### 3. 语义层面
- [ ] 每个字段的业务含义是什么？（问用户或查口径文档，别猜）
- [ ] 数据是明细级还是已经聚合过的？（聚合过的数据再聚合会失真）
- [ ] 单位是什么？（元/万元/套/人/天）

## 画像输出格式（示例）

> 字段名用通用占位（`entity_l3`/`metric_x`/`price_field`），实际业务字段按 `domain-mapping.md` 替换。

| 字段 | 类型 | 非空率 | 样例 | 异常 | 备注 |
|------|------|--------|------|------|------|
| entity_l3 | 文本 | 100% | A栋 | 无 | 可能跨组重名，聚合要复合key |
| metric_x | 数字 | 92% | 35 | 有 8% 空值、3 个负值 | 空值需处理 |
| price_field | 数字 | 100% | 1800 | `"1,200"` 文本混入 | 需清洗 |

## 规则

1. **手工提供的文件，默认假设数据质量有问题**——先验证再分析
2. 画像发现问题，不要自己默默修，列出来给用户看，问怎么处理
3. 数字字段转 Number 失败时**记 warning**，不要吞掉——静默 = 数据悄悄错
4. **画像确认前不允许进入聚合**：画像表给用户确认「异常都处理好了」之前，禁止写聚合逻辑。测试演示流程也不例外——跳过确认 = 污染结果直接进看板

## 来自真实案例

经营日报 Excel：表头行有全角/半角括号混用、空行混在数据中间、数字列有 `-` 占位。这三类问题不处理，聚合结果全是 NaN 或静默丢数据。
