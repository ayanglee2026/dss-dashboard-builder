# 数据验证检查清单（Data Validation）

> **依赖与前置**
> - 前置：`domain-mapping.md`（识别业务实体层级 / 唯一 ID 用哪个字段）
> - 被依赖：`metric-dictionary.md`（验证字段 → 口径表直接字段）、`excel-import.md`（验证发现的清洗规则）、`metric-library.md`（五维验证的总纲）
> - 阶段 3「MVP 数据验证」时读这篇。字段的「范围及定义」在阶段 1 单独确认，本清单专注「数据对不对」。

> ⚡ **先跑工具，再对照清单**：`python3 tools/profiler.py <文件> --output 画像.md` 自动生成字段画像 + 异常清单（字段类型/非空率/唯一值/负数/超大值/重复 key/脏值占位）。本清单的机械检查项工具已代劳，你只需确认「语义」和「异常是否属实」——别再用肉眼逐项数。

数据验证的目标：**数据没坑 + 指标算法算得对**。核心方法是对账——独立核算 + 自动校验，不靠肉眼看。验证五维见 `metric-library.md` 第 3 步，本清单是其中「数据质量」维度的逐项检查项。

## 输出物

一张《数据验证报告》，每项「预期 vs 实际 → 通过/失败」，给用户确认失败项处理方式后再进入指标库发布。

## 检查清单

### 1. 结构层面
- [ ] 字段清单：一共几列？每列是什么类型（文本/数字/日期/布尔）？
- [ ] 行列规模：多少行数据？多少条记录？
- [ ] 主键：有没有唯一标识？（没有的话，聚合时用什么做 key？）

### 2. 质量层面（默认有坑，逐项验证）
- [ ] **缺失/空值**：哪些列有空白？占比多少？
- [ ] **异常值**：负数（不该有的）、超大值、超小值、0 占比异常高
  - **超大值/超小值判据**：`值 > 该列中位数 × 10` 或 `超出业务上限`（口径表定义的合理范围）→ 标记「待确认」，不得直接参与聚合。**注意：中位数×10 会误报大楼栋正常库存**（真实案例：总库存中位数 3、×10=30，把 43/46 的正常大楼栋标成异常）。判据要结合业务上限，先确认「这个字段多大算正常」再下结论
  - 负数：口径不允许负的列出现负值 → 标记（净增长/净新签类指标负值是正常的，别误报）
  - 0 占比异常高（>30%）→ 确认是真 0，还是缺省值被填成了 0
  - **整列全 0**：某字段整列全是 0，要么「本期无此业务」要么「字段已废弃」——**必须问用户，别默认对**（真实案例：企业退租列 360 行全 0，待确认废弃）
- [ ] **格式不一致**：
  - 同列混多种格式（如日期有 `2026/7/1` 和 `2026-07-01`）
  - 数字列混进文本（如 `"1,200"`、`"约200"`、`"--"`）
  - 表头有全角括号、多余空格、换行符（`normalizeHeader` 要处理）
- [ ] **重复**：同一行出现两次？同 key 出现两次（会静默覆盖/累加）？
- [ ] **脏值占位**：`-`、`--`、`NULL`、`(null)`、空字符串当成了真数据？

### 3. 语义层面
- [ ] 每个字段的业务含义是什么？（问用户或查口径文档，别猜）
- [ ] 数据是明细级还是已经聚合过的？（聚合过的数据再聚合会失真）
- [ ] **有没有父级合计/上报字段混在明细里？**（如「门店合计」「上报总数」这类列是父级合计值，聚合时放进 SUM_FIELDS 会翻倍——标记为非聚合字段，交叉校验时单独取值，见 `excel-import.md`）
- [ ] 单位是什么？（元/万元/套/人/天）

## 画像输出格式（示例）

> 字段名用通用占位（`entity_l3`/`metric_x`/`price_field`），实际业务字段按 `domain-mapping.md` 替换。

| 字段 | 类型 | 非空率 | 样例 | 异常 | 备注 |
|------|------|--------|------|------|------|
| entity_l3 | 文本 | 100% | A栋 | 无 | 可能跨组重名，聚合要复合key |
| metric_x | 数字 | 92% | 35 | 有 8% 空值、3 个负值 | 空值需处理 |
| price_field | 数字 | 100% | 1800 | `"1,200"` 文本混入 | 需清洗 |

## 规则

1. **手工提供的文件，默认假设数据质量有问题**——先验证再分析
2. 画像发现问题，不要自己默默修，列出来给用户看，问怎么处理
3. 数字字段转 Number 失败时**记 warning**，不要吞掉——静默 = 数据悄悄错
4. **画像确认前不允许进入聚合**：画像表给用户确认「异常都处理好了」之前，禁止写聚合逻辑。测试演示流程也不例外——跳过确认 = 污染结果直接进看板

## 来自真实案例

经营日报 Excel：表头行有全角/半角括号混用、空行混在数据中间、数字列有 `-` 占位。这三类问题不处理，聚合结果全是 NaN 或静默丢数据。
