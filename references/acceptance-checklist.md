# 验收清单（模块级分层验收）

> **依赖与前置**
> - 前置：`metric-dictionary.md`（对照口径表核对派生指标）、`assembly-config.md`（验收标准来源）
> - 被依赖：无
> - 阶段 8 模块级验收时读这篇。

验收标准**在阶段 5 组装时就定**（不是验收阶段才想）。每个模块每选配一个功能，同步写一条「用户视角」的验收标准，阶段 8 按清单逐条验。验收 = 满足使用场景，不是功能做完。

## 模块级验收

**每个模块一份验收清单**，不是整个看板一份。多模块看板逐个模块过，每模块三层递进：数据准确性 → 功能完整性 → 交互可用性。验收标准来自该模块的组装配置表（`assembly-config.md`），「选配了什么，就验什么」。

## 第一层：数据准确性（最高优先）

数据错，页面再好看也是废的。

- [ ] 表头缺失列在解析时被拦截并报错（没静默填 0）
- [ ] 数字字段清洗成功（`-`、空、文本混数字都处理了）
- [ ] 聚合树父节点 = 子节点求和（sum 一致性校验通过）
- [ ] 两个视角的叶子节点总数一致（key 冲突排查过）
- [ ] 派生指标公式跟口径表一致（对照口径表逐项核对）
- [ ] 交叉校验无 mismatch（或 mismatch 已列出给用户确认过）
- [ ] 抽样核对：手工挑 2-3 个明细，看板上的值能对上

## 第二层：功能完整性

- [ ] 用户点名要的功能全有（用需求清单逐条勾）
- [ ] 核心流程闭环：导入/加载 → 展示 → 导出/上传，一条龙走通
- [ ] 空态处理：无数据时页面不报错、有友好提示
- [ ] 错误态处理：导入坏文件、后端挂掉，有明确提示而不是白屏

## 第三层：交互可用性

- [ ] 筛选器对图表/表格**真的生效**（不只是 UI 变化）
- [ ] 视角切换 / 树钻取能展开收起
- [ ] **滚动/图表渲染必须实测**：真滚一遍 + 查 DOM overflow，不能靠 scrollHeight 推断（有真实教训：算出来不滚动，实际溢出了）
- [ ] 加载中有提示（转圈/文字），不是白屏干等
- [ ] 数据量大时页面不卡死
- [ ] 每个主要功能都能**自动化测试**跑通（如 Playwright），不手动点验

## 第四层：间接用户可用性（成品交付前必验）

> 完整标准见 `end-user-usability.md`。成品交付给不懂技术的最终使用者前，逐条核验。

- [ ] 成品有内置操作指引，间接用户首次打开能看懂
- [ ] 指标说明页可达，间接用户能自助查口径
- [ ] 状态/错误提示是非技术用户能懂的文案（对照 end-user-usability 第 4 节标准）
- [ ] 导入/导出/筛选间接用户能自主操作
- [ ] 规则有说明页，间接用户能看懂为什么被预警
- [ ] 待办能标记状态、回写结果
- [ ] 策略建议有执行记录入口，间接用户能记录执行了什么

## 验收执行方式

### 自动化测试优先（推荐）

单文件 HTML 项目用 Playwright 做自动化验收。**每个启用的应用层选项 ≥1 条断言**，测用户视角（UI 状态 / 数据值变化），不是测函数返回值：

```bash
# 起本地服务 + Playwright 脚本点一遍所有功能
python3 -m http.server 8888
node test.js   # Playwright：数据对账→筛选→视角→导出→权限
```

- 数据准确性用「独立核算」：脚本里从 RAW_DATA 独立算预期值，对比页面显示（不依赖页面自己的渲染逻辑）
- 能自动化的验收点全部自动化，跑通才算完。涉及图表/滚动渲染的，脚本里**查 DOM 的实际状态**（canvas 尺寸、overflow），不要只看函数返回值

### 降级方案：无 Playwright/node 环境

适用：WorkBuddy 沙箱、用户本地无 node、纯静态预览等跑不了 Playwright 的场景。**保留 Playwright 为推荐项，降级是兜底，不是替代，更不是降低标准——交互可用性的检查项一条不少，只是换执行方式。**

1. **人工走查清单**：按「第三层：交互可用性」逐条手动点验，每条勾选留记录
2. **DOM overflow 检查**（替代脚本查 overflow）：
   - 浏览器 F12 → Elements → 选中滚动容器 → 看 CSS `overflow` 属性 + 实际 `scrollHeight > clientHeight`
   - 重点查：表格、图表容器、弹窗内容区，是否真溢出但不滚动
3. **数据对账**（替代脚本独立核算）：手工挑 2-3 个明细，对照看板显示值核对
4. **图表渲染**：肉眼确认 canvas/svg 有内容 + 窗口缩放（拖拽浏览器宽度）不变形不溢出
5. **空态/错误态**：导入空文件、断网模拟后端挂，看提示是否友好（对照 `end-user-usability.md` 第 4 节文案标准）

**降级验收记录**：把走查结果写进《验收报告》，注明「人工走查（无 Playwright 环境）」，同样算验收通过。自动化能覆盖的部分仍优先自动化，降级只补自动化跑不了的部分。

### 人工过一遍场景（测不了的列清单）

站在使用者的角度，用真实数据走一遍完整流程：拿到一份数据 → 导入/接入 → 看数据对不对 → 筛选 → 导出 → 给同事看。

**自动化测不了的列清单叫用户补测**：真实上传云端、邮件/企微推送、真实网络环境下的历史回看等。
