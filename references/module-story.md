# 模块定义卡 + 启动前准备（Module Story）

> **依赖与前置**
> - 前置：无（开工第一个读）
> - 被依赖：`metric-dictionary.md`（指标从目标卡的关键指标自然带出）
> - 可独立读。

阶段 0 的核心产出：把「做个数据看板」这个模糊需求，落成一张**可执行的目标卡**，作为后续所有开发的中心依据。

## 为什么先定目标卡

看板主题（经营/库存/销售……）只是外壳，由「看什么指标」自然带出。真正要对齐的是：**给谁用、解决什么问题、什么算做完**。目标卡写清楚这三点，阶段 5 组装、阶段 7 验收都回看它。

## 用户故事（填空式）

**不问「用途类型」**（监控型/分析型/汇报型这类选择题会让用户困惑，而且用途在用户故事里已经表达了）。让用户填三空：

```
作为___，我要___，以便___
```

- 作为 = 角色（店长/管理层/运营/老板）
- 我要 = 动作（看到什么/做什么）
- 以便 = 价值（及时发现问题/快速决策/向上汇报）

例：`作为店长，我要看到自己管辖楼栋的入住率和新签退租，以便及时发现经营异常调整打法`

> 一个看板可以有多个用户故事（不同角色）。用途（监控/分析/汇报）由「以便___」推断，不用单独问。

## 成功标准（可衡量）

「做完了」不等于「满足场景」。成功标准要可衡量：

- ❌ 「做一个经营看板」
- ✅ 「管理层每天 5 分钟看懂全公司经营健康度」「异常楼栋 24h 内被识别并派单」

## 模块拆分

大看板拆几个模块？一个模块 = 一张目标卡。拆分依据是**数据主题**（不是页面板块）：

- 单模块：一份宽表、一组相关指标（如经营日报）
- 多模块：多份宽表各自成模块（如经营日报 + 库存分析），共享导航和权限

## 目标卡模板

```markdown
# <模块名> - 项目目标卡

## 用户故事
| 角色 | 我要 | 以便 |
|------|------|------|
| ... | ... | ... |

## 成功标准（可衡量）
1. ...

## 数据源
- 基础数据：<文件/库/接口>，<粒度>，<列数×行数>

## 权限范围
| 角色 | 权限 |
|------|------|
| ... | ... |
```

## 启动前准备 checklist（用户自查）

开工前让用户备齐，缺了先补：

- **数据（必须）**：至少 1 份数据宽表（Excel/CSV，或数据库连接信息/接口文档）；知道每列字段含义（或愿意现场逐列确认）；知道数据更新方式（谁更新、多久一次）
- **目标（必须）**：一句话说清「给谁看、解决什么问题」；一个可衡量的成功标准
- **使用人（必须）**：谁在用（内部几人/对外/分角色）；要不要登录、分权限
- **指标（可选）**：大致想看哪些核心指标（Top 3–5，没有就由 skill 引导）
- **部署（可选）**：要不要多人共享数据；有没有现成服务器/数据库
- **验收配合（可选）**：有没有人能帮忙测「自动化测不了的功能」（真实上传云端、邮件推送）

没备齐时用 3 问兜底：**谁在用？看什么指标？数据从哪来？** 不反复追问，先给合理假设让用户纠正。
